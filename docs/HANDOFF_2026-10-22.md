## First steps on the laptop

1. Clone `https://github.com/drelomrania-dev/Dental-Spa.git` and use `main`.
   Install Node.js and pnpm, then run `pnpm install` and `pnpm e2e:install`.
2. Run `pnpm verify:release` for the build and demo/public browser suite.
   Check the actual results; 11 guarded tests are expected to skip without
   the local Auth/backend target.
3. Get Docker Desktop's Linux engine running and confirm `docker info` works.
   Follow `docs/LOCAL_DEVELOPMENT.md`: `./scripts/local-start.ps1 -Reset`,
   `./scripts/local-sql-tests.ps1`, then `./scripts/local-e2e.ps1` in PowerShell.
   `-Reset` affects the **local** Supabase database only. Use synthetic data.
4. Investigate and fix any runtime failures. Complete the two-client booking
   race, token management, invitation/claim, intake media withdrawal and full
   two-clinic journey listed in `PHASE_10_STATUS.md`. Record exact outcomes in
   the test report and update the phase status before calling local acceptance
   complete.

The local scripts create an ignored `.local-fixtures.json` with synthetic test
credentials. Create `.env.local` from `.env.example` for any separate target;
environment files, real credentials, service-role keys and fixture output are
not part of the Git handoff. `docs/E2E_RUNBOOK.md` explains staging-only
authenticated browser checks.

## Product/release decisions still open

The reminder sender makes no provider call. A trusted scheduler/worker,
approved templates and consent/retention policy are needed before real email
or WhatsApp delivery. Remote release verification, recoverable backups and a
restore drill, monitoring, clinic workflow sign-off, and Moroccan legal/tax/
receipt/clinical retention decisions remain open. See `RELEASE_READINESS.md`;
the project is not ready for real patient or financial data.
